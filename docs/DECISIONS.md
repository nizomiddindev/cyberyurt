# Architectural & Product Decisions

Every time a task introduces or changes a decision, add a new row to this table.

| Date | Decision | Why | Alternatives rejected |
| --- | --- | --- | --- |
| 2026-11-26 | Uzbek (Latin) first; all UI text stored in `src/locales/uz.json` with no hard-coded UI strings | Serves kids in Uzbekistan first while making it easy to add Russian and English later | Hard-coding Uzbek strings directly in JSX components; starting in English only |
| 2026-11-26 | Three user roles: `student`, `teacher`, `admin` | Covers learners, classroom educators, and content maintainers without overcomplicating permissions | Single user role with no teacher tools; complex custom RBAC system |
| 2026-11-26 | Next.js + TypeScript on Vercel with Supabase (Postgres + Auth) and Row-Level Security (RLS) | Fast full-stack TypeScript workflow, free/low-cost hosting, and strong database-level access control | Separate backend server (Express/Django) + self-hosted Postgres; Firebase without SQL |
| 2026-11-26 | Modular platform structure: Learn, Practice (CTF + point-cost hints), Labs, Compete, Teacher tools, Gamification, Admin panel | Supports both guided learning and hands-on cybersecurity practice in classrooms and competitions | Standalone CTF-only site without lessons or teacher tracking |
| 2026-11-26 | Store only flag hashes, verify flags server-side only, rate limit to 5 attempts/minute/user, never expose flags in client code | Prevents students from inspecting client code or brute-forcing flags | Checking flags in client-side JavaScript; storing plaintext flags in the database |
| 2026-11-26 | Browser terminal uses `xterm.js` + TypeScript simulated shell (Phase 1–2), optional `v86` real Linux later (Phase 3) | Fast startup, zero server cost per student, safe in-browser execution, and clean open-source licensing | WebVM / CheerpX (rejected due to license); cloud-hosted Linux containers per user (high cost and security risk) |
| 2026-11-26 | Store terminal files in browser OPFS (`/users/<id>/`, shown as `/home/<username>`, with `~/challenges/<challenge-id>/`, `/tmp` cleared each visit, plus upload/download/reset); store progress/XP/solves in Supabase | Zero cloud file storage cost and fast local file access while keeping learning progress synced and authoritative in Supabase | Storing terminal files in cloud object storage; storing progress/XP in browser storage |
| 2026-11-26 | Terminal username matches registration username with prompt `"<username>@<platform>:~$"`; guests use `"mehmon"` with no saved progress | Gives students a realistic Linux-like identity while letting visitors try the platform without an account | Generic hardcoded prompt for all users; forcing registration before trying the terminal |
| 2026-11-26 | Strict username rules (`a-z`, `0-9`, `_`, `-`, starts with letter, 3–20 chars, unique, reserved names `root`, `admin`, `mehmon`, `system` blocked) plus separate free-text display name | Keeps usernames safe for Linux paths/prompts and URLs while letting students show their real name (e.g., `O'tkir Karimov`) | Allowing spaces/special characters in usernames; using only a single name field |
| 2026-11-26 | Serve challenge files as static site assets and restrict terminal `wget` to our own domain | Simple, reliable hosting and prevents students from using the terminal to fetch arbitrary external URLs | Hosting challenge files on third-party servers; unrestricted `wget` access to any domain |
| 2026-11-26 | Collect minimum personal data (username, display name, class, progress) | Protects children's privacy and reduces security/compliance risk | Collecting phone numbers, home addresses, dates of birth, or unnecessary tracking data |
